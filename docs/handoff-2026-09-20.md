## What the project is

TravelStan is a server-rendered Django 5.2 flight comparison app. It accepts
origin, destination, dates, cabin, date flexibility, and a checked-bag
requirement. Search results are normalized into offer cards with itinerary,
baggage, price, source status, freshness, and an optional safe booking link.

Search does not write to the database, cache, session, or logs. The app does
not sell tickets or take payment. It is intentionally JavaScript-free.

## Provider configuration and the current blocker

The running process is configured as:

```text
TRAVELSTAN_PROVIDERS=synthetic_demo
AFKL_API_KEY=missing
SINGAPORE_API_KEY=missing
TUI_API_KEY=missing
```

That is why the page shows generated itineraries. This is deliberate fail-closed
behavior: the app never presents fictional rows as real fares and never falls
back to synthetic results after an external provider fails.

The existing adapters are in `flights/providers/`:

| Provider | Code status | What is still needed |
| --- | --- | --- |
| Air France–KLM Offers | Implemented behind `AFKL_API_KEY` | Create developer app, obtain key, validate one real request, then assess production status and booking response |
| Singapore Airlines Flight Search | Implemented behind `SINGAPORE_API_KEY` | Trial/test registration is available; production requires provider approval/contract and a production secret |
| TUI Flight Offers | Implemented behind `TUI_API_KEY` | Obtain key and validate live access; current booking flow requires session initialization and redirect update calls |

No key is present in the workspace, and no provider account was created during
implementation. A real offer cannot be produced until at least one provider
key is supplied in the server process. Never put a populated key in this
repository or send it in chat.

Example activation after obtaining an Air France–KLM key:

```bash
export TRAVELSTAN_PROVIDERS=afkl
export AFKL_API_KEY='your-local-key'
export AFKL_DATA_STATUS=trial
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python manage.py check
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python manage.py runserver 127.0.0.1:8002 --noreload
```

Only change `AFKL_DATA_STATUS` to `live` after validating that the account is
returning current production data and that the displayed seller/booking link
matches the provider response.

## Provider investigation result

The original requirement was a lawful, custom comparison table with current
fares, bounded searches, honest baggage semantics, and a safe booking path.
The current findings are:

| Candidate | Free/self-service finding | Booking/data fit | Decision |
| --- | --- | --- | --- |
| Air France–KLM Offers | The current developer portal catalog marks Offers access as “Everyone” and says API usage is free of charge. An application and API key are still required. | Strongest fit among investigated options: ticket availability/prices and a path to complete booking on the airline website. Exact current quota and production approval still need validation with a real account. | Best next provider to activate |
| Singapore Airlines Flight Search | Official registration/trial access is available for the test environment. Production access requires contractual terms/approval and a production secret. | Useful native flight search and flexible-date request, but test data is not real inventory. | Keep as trial adapter; not a confirmed free production source |
| TUI Flight Offers | API key required; no confirmed recurring free allowance was found. | Flight offers and extras are available. Current live docs require initialize-session and update-session/in-start redirect calls before a reliable booking deep link. | Conditional; validate account and flow first |
| Turkish Airlines | Official portal documents a sandbox quota of 3,000/day, but production requires consultation/agreement. | Sandbox is not real bookable inventory; not integrated. | Not a free live solution |
| Amadeus | Current official site says the self-service portal was decommissioned on July 17; enterprise access remains. | Previously attractive API shape, but no new personal self-service path. | Remove from shortlist |
| Lufthansa Group | Registration was on hold in the earlier first-party check. | Partner access may provide airline links, but it is not currently obtainable as a personal self-service source. | Blocked |
| SerpApi Google Flights | Free plan advertises 250 successful searches/month, enough for exact searches at this scale. | It is a scraping intermediary; checked-bag proof, airline-direct links, retention, and amplification remain unsuitable under the original rules. | Only a separately approved personal experiment |
| Skyscanner | Partnership application rather than open self-service free access. | Booking-generation and partner restrictions conflict with the product boundary. | No-go |
| Travelpayouts | Search API rules require user-initiated full-result display and booking conversion; links may lead to agencies or brands. | Conflicts with comparison-only behavior and airline-direct proof. | No-go |
| Duffel | Commercial/booking-oriented offer-to-order product with look-to-book constraints. | Not suitable for this comparison-only app. | No-go |
| Google Flights partner access | Invite/NDA partner access. | Not a public developer path. | No-go |
